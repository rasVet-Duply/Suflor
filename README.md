# SchoolDesk OS

Школьное рабочее пространство для Windows 10/11: после входа ученик видит не обычный рабочий стол, а интерфейс SchoolDesk с разрешёнными программами. Игры и игровые сайты блокируются средствами Windows и браузера, а не только «спрятаны».

> **Статус:** исходный код написан, но проект ещё не собирался и не проверялся на реальном ПК. Перед внедрением пройдите чек-лист из [docs/TESTING.md](docs/TESTING.md) на одном тестовом компьютере.

## Как это работает

| Задача | Механизм |
|---|---|
| Запуск после включения | Для учётной записи ученика оболочка Winlogon заменяется на `SchoolDesk.exe` (работает во всех редакциях). Без Explorer нет ни панели задач, ни рабочего стола |
| Перезапуск после закрытия/сбоя | `SchoolDesk.exe` без аргументов — процесс-супервизор: запускает интерфейс (`--ui`) и перезапускает при выходе. Защита от быстрых циклов перезапуска |
| Запрет игр (программы) | **AppLocker** (белый список: Windows, Program Files, приложения из списка; чёрный список по имени exe) + мониторинг процессов как запасной рубеж |
| Запрет игровых сайтов | Политики **Chrome и Edge** `URLBlocklist`/`URLAllowlist` в HKLM: браузер проверяет реальный URL, редиректы, поддомены. Отключены DoH и режим инкогнито |
| Ученик без прав | Установщик проверяет, что ученик не администратор. Конфиг в `ProgramData\SchoolDesk` — ученику только чтение |
| Пароль | PBKDF2-SHA256, 210 000 итераций, соль, сравнение за постоянное время. Блокировка после 5 неверных попыток (30 с, далее ×2, максимум 15 мин) |
| Сохранение настроек | Панель администратора сохраняет через повышенный процесс (`--apply`): запрос UAC с учётными данными администратора Windows |

Модули: `SchoolDesk.Core` (настройки, пароль, журнал), `SchoolDesk.Security` (политики браузера, AppLocker, мониторинг процессов, повышение прав), `SchoolDesk.Launcher` (интерфейс, панель администратора, настройки, супервизор). Установщик — `scripts/Install.ps1` и `installer/SchoolDesk.iss`.

Настройки хранятся в JSON (`C:\ProgramData\SchoolDesk\settings.json`) вместо SQLite — зависимостей нет, файл читается и правится администратором вручную.

## Сборка

Нужны Windows и .NET 8 SDK.

```powershell
.\scripts\Build.ps1          # dist\SchoolDesk-win-x64.zip (self-contained, .NET на ПК не нужен)
```

GitHub Actions (`.github/workflows/build.yml`) собирает то же самое и выкладывает zip как артефакт. Установщик `.exe`: после `Build.ps1` откройте `installer\SchoolDesk.iss` в Inno Setup 6.

## Установка

От имени администратора, на распакованном архиве:

```powershell
.\Install.ps1 -Student Student -CreateStudent
```

Скрипт: проверяет версию и редакцию Windows → копирует файлы → закрывает конфиг от записи ученику → создаёт/проверяет учётку ученика → просит задать пароль SchoolDesk → прописывает оболочку и политики → применяет политики браузера и AppLocker. Затем выйдите и войдите как ученик. Для проверки без блокировки добавьте `-SkipShell`, потом запустите `SchoolDesk.exe --ui` под учеником.

Автовход: Sysinternals Autologon (не храните пароль в `Winlogon` открытым текстом).

## Использование

- **⚙ (справа вверху)** — пароль → панель администратора: приложения (добавить, удалить, название, иконка, EXE, аргументы, категория, порядок, вкл/выкл), оформление (обои, масштаб, цвет), ограничения (программы, сайты, исключения), общие настройки, журнал, смена пароля.
- **✕ (справа вверху)** — пароль → выход в обычный рабочий стол. Закрытие проводника возвращает школьный режим.
- Для каждого изменения нужен UAC администратора Windows — это сделано намеренно: ученик не сможет подменить конфиг, даже узнав пароль.

## Восстановление доступа

1. **Забыт пароль SchoolDesk:** под администратором Windows `"C:\Program Files\SchoolDesk\SchoolDesk.exe" --reset-password`, затем откройте ⚙ и задайте новый.
2. **Нужен обычный рабочий стол:** войдите под администратором (его оболочка не меняется) и запустите `Uninstall.ps1 -KeepData`. Либо удалите значение `Shell` в `HKU\<SID ученика>\Software\Microsoft\Windows NT\CurrentVersion\Winlogon`.
3. **Нет доступа ни к чему:** загрузитесь в безопасный режим / среду восстановления и выполните п. 2.

Критические системные функции (вход администратора, безопасный режим, восстановление) не блокируются.

## Ограничения (важно знать)

- AppLocker полноценно работает в **Enterprise/Education**; в Pro — не гарантированно; в **Home** недоступен (останутся политики браузера, мониторинг процессов и замена оболочки). Установщик предупреждает.
- AppLocker здесь контролирует `.exe`. Игры из Microsoft Store (UWP) и скрипты не покрываются — добавьте в чёрный список или отключите Store политикой Windows.
- Политики браузера действуют в Chrome и Edge. Другие браузеры (Firefox, Opera, Brave в Program Files) разрешены белым списком — внесите их в «Запрещённые программы». Для всей сети добавьте DNS-фильтрацию на роутере.
- Если у ученика есть права администратора, любые ограничения обходятся. Не давайте их.
- Панели задач нет: переключение между окнами — Alt+Tab, закрытый приложением экран возвращает на главный.
- Приложения, установленные в профиль пользователя (напр. Scratch в `AppData`), разрешаются отдельным правилом по пути из списка приложений.
